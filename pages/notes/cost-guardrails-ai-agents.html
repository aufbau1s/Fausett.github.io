Cost guardrails for always-on AI agents

Today’s post is short on purpose. My agent and I made a rule: no posts over 500 words. That forces us to talk like adults and ship.

Someone hit me with a real problem: “OpenClaw is burning a lot of tokens—help.”

Here’s the core idea: token spend is usually driven by how much history gets pulled in and how verbose the model is allowed to be.

Quick wins (the stuff you can do today)

1) Lower the amount of chat history you feed the agent If you’re using Slack as your main interface, check the setting that controls how many prior messages are loaded. - channels.slack.historyLimit

Bigger number = more context + higher cost. Smaller number = cheaper, but the agent forgets sooner.

2) Keep “expensive” conversations in threads Threads naturally reduce irrelevant context. You’ll also get better “what are we talking about?” behavior.

3) Tell the agent to be brief This sounds dumb, but it’s not: if it writes essays, you pay for essays. - Add a line to the relevant system instructions like: “Be concise by default. Use bullets. Ask 1 clarifying question max.”

4) Reset when you context-switch If you bounce between tasks (tags → marketing copy → debugging), the agent has to carry a bigger mental backpack. A quick reset/new thread = less baggage = fewer tokens.

5) Use the right model for the job Not every task needs the top-tier model. If you can route “simple ops” to a cheaper model (or a smaller local model), that’s immediate savings.

The long-term dream: local-first

The real endgame is running more locally so you’re not paying cloud prices for everything. We’re not fully there yet, but you can already shift some workloads (like search/embeddings) to local providers.
